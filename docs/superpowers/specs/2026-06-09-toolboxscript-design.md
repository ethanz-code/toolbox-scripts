# toolboxscript 设计说明

## 目标

把 `toolboxscript` 做成一个可持续扩展的脚本合集仓库，用来放多种日常自动化脚本。第一批重点是企业核验类脚本，尤其是风鸟查询；后续可以继续加 Excel 处理、数据抓取、清洗、导出和批量核验脚本。

## 核心原则

- 一个仓库，多脚本入口。
- 每个脚本独立运行，互不依赖。
- 每次运行都保留完整痕迹，便于复查和重跑。
- 默认保守限速，避免触发风控。
- 输出以可交付文件为准，不只打印到终端。

## 仓库结构

- `src/`
  - `cli.py`：统一命令入口。
  - `common/`：通用工具，例如配置、日志、重试、时间戳、文件路径、Excel 读写。
  - `connectors/`：外部服务适配器，例如风鸟。
  - `runners/`：各脚本的业务流程，例如 `riskbird_company_check`。
- `data/`：输入文件和样例数据。
- `runs/`：每次运行的输出目录，按时间戳创建。
- `docs/`：使用说明、字段定义、脚本说明。

## 运行模型

每次执行都会创建一个独立运行目录，例如：

- `runs/2026-06-09_103000_riskbird_company_check/`

目录内固定保存：

- `log.jsonl`：阶段日志和逐条处理日志。
- `summary.json`：本次运行统计。
- `raw/`：原始接口响应、搜索页结果、详情页结果。
- `output/`：最终交付文件，例如 xlsx、csv。

## 风鸟脚本行为

风鸟核验脚本分四档：

- `已确认命中`：公司名和统一社会信用代码都能对上。
- `有问题`：命中注销、吊销、异常经营、非正常户、行政处罚、信用代码不一致等问题。
- `需复核`：有结果，但证据不足，不能当成已确认命中。
- `未查到`：多种检索方式都没有可用结果。

查询流程优先级：

1. 统一社会信用代码精确查。
2. 公司名查。
3. 备用关键词和补充入口查。
4. 详情页补查和交叉验证。

如果同名但代码不一致，默认不算正常，进入 `需复核` 或 `有问题`，由规则决定。

## 风控策略

- 单线程或极低并发。
- 每次请求之间加入随机间隔。
- 失败后指数退避重试。
- 同一企业只在必要时重复查询。
- 所有请求都记录状态码和失败原因。

## 日志与可观测性

终端输出只保留简短进度；详细信息写入文件：

- 运行开始和结束时间。
- 每个阶段的耗时。
- 每个企业的命中路径。
- 每次重试的原因。
- 每个结果的判定理由。

## 扩展方式

新增脚本时只需要新增一个 `runner`：

- 定义输入。
- 定义执行流程。
- 定义输出文件。
- 复用公共日志和重试工具。

这样后续新增脚本不会互相污染，也能共享统一的运行目录和日志格式。

## 交付要求

- 每个脚本都要有 README 说明用途、输入、输出、运行方式和风控注意事项。
- 每次运行都必须能回溯到原始请求和原始响应。
- 最终结果优先输出 xlsx，其次 csv。
